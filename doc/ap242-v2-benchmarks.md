# AP242 API v2 Output Benchmarks

This file records comparable measurements for the staged API v2 output
work.  It is intended to make changes in generated output cost visible in
the commits which introduce them.

## Method

The measurements were made on 2026-08-02 with GCC 13.3.0 and C++11.

The schema under test was BRL-CAD's `ap242e4.exp` conversion schema.
The real exchange-file workload was the NIST STC 09 ASME AP242 edition
4 sample, `nist_stc_09_asme1_ap242-e4.stp`.

The generator used `--late-bound`, the default 64-entity and 8-type chunk
limits, and a release STEPcode build.  Compilation used `-O2 -fPIC` and two
concurrent compiler processes.  Generated-output counts include `.cc`, `.h`,
and `.cmake` files through directory depth two.  The baseline is commit
`fa2758c5` before recommendations 1--4.

to descriptor slots.  It is recorded here because the packed schema image

## Recommendations 1--4

This stage adds stable entity, type, and attribute IDs through `SchemaModule`,
makes compatibility entity names opt-in for late-bound output, moves schema
rules and complex-entity support to runtime-consumed tables, and writes late
entity metadata directly to bounded chunks instead of creating 4,814 leaf
files.

The real AP242 exchange-file check created and validated 10,609 instances
with zero errors and zero warnings.  Its 949,685-byte rewritten Part 21 file
matched the baseline apart from the expected `FILE_NAME` timestamp.

## Recommendation 5

This stage resolves each late-bound entity's flattened attribute layout once
after schema initialization.  Instance construction then follows descriptor
and index records directly instead of recursively walking supertypes and
repeating attribute-name searches.  The cache is external to
`EntityDescriptor`, so its object layout and the API v1 ABI are unchanged.

The construction benchmark uses the 1,531 `DIRECTION` instances in the real
exchange file and repeats that population 1,000 times.  This isolates the
work changed by this stage while retaining a type and frequency from the
AP242 workload.  Results are the median of three runs.

|---|---:|---:|---:|

| Construction user time | 0.82 s | 0.61 s | -25.6% |

The complete exchange-file check still created and validated 10,609

949,685 bytes and differed from the previous stage only in the expected
`FILE_NAME` timestamp.  Generated schema file counts, source size, and the
schema shared library are unchanged because this is a shared-runtime change.

## Recommendation 6

This stage replaces the generated `SchemaModuleSlot` pointer arrays with a
16-byte, relocation-free `SchemaModuleImage`.  Shared initialization helpers
capture descriptor pointers in stable generated-ID order and transfer those
vectors to `SchemaModule` after initialization.  The older slot-based entry
point remains available for existing generated API v2 code.

Source and binary measurements compare recommendation 5 with the packed
image.  Compile times use matching clean CMake builds with two compiler
processes.  Read/write times are medians from paired 20-run batches.

| Measurement | Recommendation 5 | Recommendation 6 | Change |
|---|---:|---:|---:|
| Generated files | 905 | 905 | unchanged |
| Generated lines | 123,552 | 117,046 | -5.3% |
| Generated bytes | 9,804,680 | 9,060,249 | -7.6% |
| Schema module source | 808,907 B | 64,367 B | -92.0% |
| Schema module source lines | 7,280 | 773 | -89.4% |
| Compile/link wall time | 41.38 s | 41.49 s | no measurable change |

| Schema shared library | 7,728,384 B | 7,470,304 B | -3.3% |

The image removes 6,498 per-descriptor pointer relocations.  The shared

bytes smaller.  Generated API v1 output and the conventional public entity

The complete exchange-file check again created and validated 10,609
instances with zero errors and zero warnings.  Its 949,685-byte rewrite
differed from recommendation 5 only in the expected `FILE_NAME` timestamp.

## Recommendation 7

This stage replaces the remaining generated descriptor procedures with one
bounded, offset-based schema image.  The shared loader validates every array,
string, range, descriptor reference, schema binding, and complex-entity tree
before it changes the registry.  It then constructs the descriptor graph with
an explicit per-load context; the process-global capture path remains only for
older generated API v2 code.  Complex-entity metadata uses the same packed
representation and validation model.

Source and binary measurements compare recommendation 6 with the complete
descriptor image.  Compile times use clean CMake builds with two compiler
processes.  Read/write times use matching 20-run batches.

| Measurement | Recommendation 6 | Recommendation 7 | Change |
|---|---:|---:|---:|
| Generated files | 905 | 865 | -4.4% |
| Generated lines | 117,046 | 86,400 | -26.2% |
| Generated bytes | 9,060,249 | 4,865,657 | -46.3% |
| Entity initialization chunks | 38 | 0 | -100.0% |
| Compile/link wall time | 41.49 s | 18.71 s | -54.9% |
| Compile/link peak RSS | 208,188 KiB | 208,528 KiB | +0.2% |
| Schema shared library | 7,470,304 B | 3,503,352 B | -53.1% |
| ELF relocations | 33,221 | 9,620 | -71.0% |
| 20 full read/write runs | 5.07 s | 4.97 s | -2.0% |
| Full read/write peak RSS | 85,572 KiB | 82,916 KiB | -3.1% |

The image removes the 2,407 generated entity initialization functions and
23,601 additional relocations.  The generated schema library is 3,966,952
bytes smaller, while its existing typed SELECT and enumeration factories
remain available for this transitional stage.

The complete exchange-file check created and validated 10,609 instances with
zero errors and zero warnings.  Its 949,685-byte rewrite retained the same
semantic result as recommendation 6.

## Recommendations 8 and 9

This stage makes the compact late-bound output independent of generated type
classes.  Shared descriptor-driven implementations now construct SELECT,
enumeration, and aggregate values, including nested values and BOOLEAN or
LOGICAL aliases.  Enumeration elements and renamed USE or REFERENCE items are
retained in the packed image.  The conventional early-bound API v1 and API v2
paths still emit their schema-specific type classes.

The generated schema header is now a dependency-bounded consumer interface.
It contains stable entity, type, and attribute IDs plus `SchemaModule` lookup
functions, and includes only `schemaModule.h`.  Runtime and model-construction
declarations remain in the internal `schema.h` umbrella.
